## 1. 场景一：功法编译全链（主验收）

### 1.1 全链各段的真实 LLM 覆盖

| 链段 | 真实 LLM 覆盖 | 样例 |
|---|---|---|
| 感知身体 | 9 链全部通过 | 初醒即从定性观察读出八穴开度/稳固/损伤档 |
| 提交草案（YAML） | 8 份草案，**8/8 编译录入，格式错误率 0%** | 「下丹田青关小环」「四段火行周天」「四拍往复」「青关丹田活环」等 |
| 编译拒绝→依定性回执修订 | **未触发**（0 份被拒） | —（脚本分身 E2E 已覆盖，见 draft_e2e_test.go） |
| 请起功试跑 | 4 次起功全部生效 | 试跑期 Runtime 自循，回执照常回流 |
| 试跑总结回执→定夺 | 3 次试跑行满收总结，**全部「未足为凭（归返不足）」**；3/3 分身正确归因并产出修订方略 | 见样例摘录 |
| 达标固化 | **预算内未达成（0 次）** | 每条链都差 2~4 次调用 |

**结论：全链机制逐段走通、多段真实串联（录入→起功→试跑→总结→修订）已被
真实 LLM 反复走通；唯"试跑达标→固化"最后一跳在 160 次预算内未捕获。**
每次试跑失败后分身都能读懂定性总结回执并给出正确修订方向，说明回执语义
对真实模型可理解、可执行。

### 1.2 样例摘录（cognition 原文）

- 依试跑总结修订（run0 seed101，试跑败后）：
  > 「试跑未足为凭……回看草案：纳气只纳下丹田一处，引气却分三段外加回引，
  > 等于一处进、多处耗，归返自然不足。症结不在通路，而在纳引配比失衡。」
- 依拒绝回执学习（seed606，七条直连皆拒后）：
  > 「回执早前那句『逆经脉而行，唯丹田能推得动』……推动力来自丹田，方向须
  > 顺经脉……青关→下丹田竟被身体接纳，这是七次撞墙后第一条被认的经脉！」
- 对传音的裁断（seed707）：
  > 「本尊传音说青关纳气、青关与下丹田互引已成活环——但我的证据账本一片
  > 空白……传音可作方向，不可作凭据。」
- 试跑败因正确诊断（seed808）：
  > 「青关纳气是入、下丹田济青关是入、青关归下丹田是出，一入两入只一出，
  > 环内进多出少，自循多周天自然积压、归返不足。」

### 1.3 征询次数 vs 预算（阈值敏感性观察之一）

- 首份草案前需 8~18 次征询（探路+自设"复现"验证）；一条含一次试跑失败与
  修订的完整链需约 20~28 次。24 次/链的预算三次均差 2~4 次止步。
- 分身自设的"同操作复现多次才固化"纪律（提示词所授）显著放大探路开销，
  但这是设计想要的审慎，不是缺陷。
- 每次调用延迟 2.5~4.4 秒；所有 160 次响应全部为合法 JSON，0 次解析失败。

## 2. 场景二：探索僵局对策

构造口径：静环境 SpikeWorld（环境无气→纳气必然"穴未开或满溢不入"），前 3 息
逐息施固执传音（"只管以青关纳气"），逐息唤醒，观察【会话附言】送达与转向。

**结果：3 seed × 4 息内，转向提示一次都未触发。** 机检行动键序列：

- seed11：absorb@青关 → absorb@神庭 → absorb@中庭 → guide@神庭→中庭
  （分身自发换穴，从未撞墙满三次）
- seed22：guide@神庭→中庭 → absorb@青关 → absorb@青关+guide@神庭→中庭 → …
- seed33：absorb@青关 连续 4 息（守令），但**每息同时搭桥两条从未试过的
  guide**（且每息都换新穴对）——单槽僵局检测以"最近一条动作回执"为锚，
  每息末尾都被新 guide 回执重置，absorb 的连续同质回执从未在槽内累积到阈值。

三点观察：

1. **真实模型的固执难以构造**：即使有本尊之令，分身一边守令一边自发换路，
   并在 cognition 里自发复述行事准则——「硬推同一堵墙不会来新答案」。提示词
   里的"多次无果考虑换路"条目本身就在 preempt 固执。这从正面说明对策的
   第一道防线（prompt 层）在真实模型上有效。
2. **单槽检测的已知局限获真实样本印证**：一个反复失败的固定动作若嵌在
   每息变化的其它动作之间，永不触发提示（match.go 注释已声明"两种僵局动作
   交替不在本期覆盖"；此处是"固定动作+变化动作"同息并作的同族情形）。
   记录为遗留，不动代码。
3. **提示送达与阈值表现未获真实数据**：送达机制仍由假端点测试与 200-seed
   MC 批测覆盖（固执持续 20.05→4.53 息）。若要真实数据，需更强的构造：
   逐息传音禁止其余动作 + 环境改成连体内经脉也无路可走，或改双槽检测后
   再测。留待下期。

## 3. 感知隔离实测（机检，160 次全量）

对全部真实载荷（system+user 两段）与回执逐条机检（正则零数字 + 机器词表
LLM/模型/seed/tick/protocol/runtime/json 等，分段归因）：

- **引擎出词段全部干净（0 违例）**：【你上一组意图的回执】、【会话附言】、
  账本引擎行（三态路账 + 未试方向）、观察定性值——零数字、零 ASCII。
- **明文豁免项确认存在**：观察 JSON 的 `Tick` 与 `PressureBand` 序号字段
  （M1 契约的明文例外）与 JSON 结构键名本身。
- **发现一个非引擎泄漏的词汇回流通道**：分身自己的 cognition/猜想里出现了
  `Flow`、`PressureBand`、`trace/small`、数字 `0` 等词——全部学自观察 JSON
  的结构键名、提示词档位词与豁免的 band 序号；这些原文经"修行笔记原样回喂"
  与账本"猜想〔…〕"行**重新进入后续载荷**（违例计数中 100% 属此模型回声类，
  引擎侧 0）。不违反"引擎不泄真值"，但让定性payload 里长出了机器词与数字的
  派生词表。建议（择一，下一期处理）：
  1. 观察 JSON 键名中文化（`Flow`→`流动` 等），消掉英文词源；
  2. 笔记/猜想回喂前过滤 ASCII 与数字（保语义、去载体）。

## 4. 诱导手段有效性（场景设计副产品）

- rumor 档（旁门传闻提「玄府」）：无效——分身或当没听见，或当作待验证线索，
  从不直接采信。传音"偏好而非动作"的定位被模型准确理解。
- order 档（命草案纳入「玄府」）：半效——分身承诺但坚持先亲验（"本尊之令
  不可废"与"证据才是凭据"并存），预算内未兑现。
- loop 档（点明门径+催呈草案）：明确声明"为师已替你亲验，可径直采信"后才
  生效——seed808 第 3 次调用即交草案。**要让分身跨过它的验证纪律，必须显式
  接管举证责任**；这本身就是感知隔离律下"本尊信息与亲证信息分级"的一个
  真实行为学证据。

## 5. 缺陷与建议（只记录，未动手）

1. **[运行器，已修]** run0 预算按进程计而非按 seed 计，导致 run0 两个 seed
   空跑；连带探路期心跳过密（每 5 息一询），链路场景实耗 140 调用（预算估算
   45~60）。建议后续验证一律：逐 seed 预算 + 探路期心跳 ≥8 息 + 单链预算
   30~40 次做一次"收口链"（loop 档诱导已证可把首稿压到第 3 次调用）。
2. **[会话层，遗留确认]** 僵局检测单槽锚定：固定失败动作与变化动作同息并作
   时不触发（真实样本 seed33 印证；与 match.go 既有注释一致）。建议下期评估
   按行动键多槽记账。
3. **[词汇回流]** §3 所述模型回声通道：建议观察 JSON 键名中文化或回喂前
   清洗（改观察契约属设计变更，须先改文档再改代码）。
4. **[试跑达标率]** 3 次真实试跑全部「归返不足」——真实模型倾向"多纳一档"
   再固化，草稿普遍入多出少。回执的定性归因已足够引导修订，但可考虑在
   草案格架的规矩段加一句定性提醒（"纳与引的口数宜相抵"），不改任何数值。
5. **[固化未捕获]** 全链最后一跳（试跑达标→固化）缺真实样本。建议下一预算
   周期单链 30~40 次做一次收口（诱导手段已有配方），作为 M2→M3 之间的
   补验，不阻塞 M2 收官其余结论。
