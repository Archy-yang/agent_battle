### WP-M2-2 功法编译端到端（验证 3/4）
- 现状缺口：Technique 编译只有单测，LLM 分身从未真实走完"观察→假设→
  设计 Protocol YAML→编译→试跑→固化"全程
- 内容：llm.go 增加 give_protocol_draft 能力（分身提交 YAML 草案→Compile
  校验→回执反馈错误定性化）；ScriptedPilot 先行，里程碑节点真实 LLM 验证
  （成本纪律：先报预算）
- 验收：脚本分身 E2E 编译出一门可验证功法；真实 LLM 一轮抽样（预算内）
- 实现定稿的语义（2026-10-07 ScriptedPilot 全链收口，补记）：
  - 新意图 give_protocol_draft(text) / start_protocol(name)：记账类，
    不打断 Runtime；会话层编译校验、定性拒绝回执（零数字零机器词，
    按"第几段"指路）。分身无数字可写，故界限（validated_range）以
    力度档词表达（`max_level`，编译期经既有 FlowForLevel 定格为区间；
    stage_3 §30 补口：分身草案的初始已知安全区由此而来，未写界限的
    通路 Runtime 一步不自循、起功即停）。
  - 试跑完毕（自然行满周天）会话层发定性总结回执并唤醒分身（stage_2
    §34 生命周期延伸）：成（stage_3 §29 达标）→ 转正并固化在案
    （进证据账本台账，成为可复用功法）；同名草案此后不可覆盖。
    不成 → 回执归纳定性败因（归返不足/稳定性不足/新增损伤/周天太少/
    有未知异象），交回分身修订。达标转正阈值未动。
  - 提示词按 R3 重排为五段（处境/行事/草案格架/身体作答/输出格式）；
    草案格架只教键名与规矩，护卫与前置条件（需阈值之数）不进分身
    表象，仍属玩家著法。

### WP-M2-3 探索僵局对策（B2 模式：探索固执）
- 现状缺口：M1 B2 因"探索固执"失败——分身反复试同一无效动作
- 内容：认知层加"无效重复检测"（同意图连续 N 次同结果 → 分身自述与建议
  转向；证据台账凸显未试方向），保持零数字
- 验收：构造固执场景的 ScriptedPilot 测试；MC 抽样固执发生率下降
- 实现定稿的语义（2026-10-07 补记）：
  - 检测在会话/认知层（match.go），非引擎物理；RuleVersion 不动。
    口径：同一行动键（同语义动作——档位/属性/流量变化不改键）连续
    三次（工程阈值，注释标明，绝不进分身侧）得到"同质回执"（主词+
    补语+方向全同）且该回执属"未见新气象"（被拒/不入/不明，或已生效
    而压力不变）→ 生成定性转向提示。已生效且有方向回应（升/降）是
    节律不是固执，反而清账。
  - 提示以回执/观察附加语（TickResult.Advice + 感知流 advice 行）呈现，
    经新可选接口 AdviceAware 注入下一息征询载荷（LLMPilot 的
    【会话附言】段；ScriptedPilot 同构消费，AfterAdvice 续接脚本可控
    地"听劝"/"固执"）。僵局持续期间每次唤醒重给，解除即撤。
  - 未试方向（knowledge.go UntriedDirections）只基于分身自己的账本
    推导：已试通路的反向 + 已知未纳气处；回执说过"目标穴位不存在"
    的名字（幻觉穴名）一律过滤，不回喂；经脉存在性不做断言（建议
    只是建议）。僵局期间账本视图凸显"未试方向："行。
  - 提示词：五段结构的【每息如何行事】内增补"多次无果考虑换路"条目，
    不另起段、不稀释。
  - MC 批测（ctmatch/stall_test.go）：200 seed × 60 息 × 开/关两臂，
    固执持续时长（首次换动作为止的息数）均值 20.05 → 4.53（听劝概率
    五成、噪声半成，两臂抽签序列同构）；同 seed 重放逐位一致。

## 5. 风险

- R1 感知流正序与"回执置顶"的交互：回执是高价值信息，正序下可能被淹没
  → 折起态只露最新，重要事件（请示/异变）考虑高亮而非置顶
- R2 单页叙事流信息密度：知识台账常驻会挤压感知流 → 展开态限高已定，观察
  用户反馈
- R3 分身提示词随语义膨胀：主环/逆流/炼化三段表象已加，继续加会稀释 →
  WP-M2-2 时重排提示词结构
