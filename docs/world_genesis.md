# World Genesis v0.1 —— 世界生成与主持层

# 0. 定位与读法

本文档是四份世界文档的第三层，回答两个此前没人回答的问题：

```text
一局世界从哪里来？（生成）
一局世界靠什么推着走？（主持）
```

```text
World Rule        架构（语法）：Entity / Intent / Observation 怎么表达
World Laws        物理（语义）：什么会发生、代价是什么、什么不可能
World Genesis     GM 层（本篇）：一局世界的生成与主持      ← 本文档
MVP / Experience  体验（流程）：玩家玩什么、数值怎么调
```

本层不新增任何物理。它只做两件事：

```text
装配：把 法则 + 场景包 + seed → 初始 World State
主持：按 tick 推进、触发预脚本化事件、判定胜负
```

核心铁律：

> **GM 不即兴。**

---

# 1. GM 的两个角色

"游戏系统当 GM"必须拆成两个角色，这是为了守住可复现性。

```text
┌──────────────────────────┐      ┌──────────────────────────┐
│ 创造者（离线）             │      │ 裁判（在线）               │
│                          │      │                          │
│ 设计场景包                │      │ 实例化初始世界             │
│ 可以是人类                │  →   │ 按 tick 推进物理           │
│ 可以是 LLM                │      │ 触发预脚本化事件           │
│                          │      │ 判定胜负                  │
│ 产出：Scenario Pack       │      │ 决定性：seed 驱动          │
│ 验证：三道关（见下）        │      │                          │
└──────────────────────────┘      └──────────────────────────┘
```

为什么这样切分：

> LLM 可以当**造物主**，不能当**故事神**。

- 创造的产物可以被验证：静态校验、引擎试跑、版本绑定。
- 即兴的行为不可复现：会毁掉 Replay、公平对抗、规则信任。

这是《World Rule》第一条公理在 GM 层的延续：

```text
LLM 决定意图，Engine 决定现实
→ LLM 决定场景，Engine 决定世界
```

## 场景包作者的三道关

未来允许 LLM（或玩家）设计场景包，但必须过：

```text
1. 静态校验    Schema 合法、资源守恒、组件合法、胜负可达
2. 引擎试跑    模拟完整对局，检查可完成性、热平衡、威胁曲线
3. 版本绑定    scenario/1.0 写入 ruleset，进 Replay
```

# 2. 场景包 Schema

场景包 = 一局世界的完整定义，是可版本化、可分享、可交换的数据。

```text
Scenario Pack {

  id / version / seed

  world {
    size / topology             # 12×12 grid
    terrain[]                   # 每格：五行偏向、阴阳偏向、通行性
    cycle?                      # 可选：环境阴阳随 tick 消长
  }

  genesis {
    entities[]                  # 初始实体：地形物、设施、资源点
    resources[]                 # 五行物料库：种类与数量
    endowment {                 # 玩家初始恩赐
      components[]
      materials[]
      energy_budget
      prior_knowledge           # 旧地图等（可能过期！）
    }
  }

  threats {
    entities[]                  # 敌人 / 中立实体（Entity + Logic）
    spawn_table?                # 程序化生成（v0.2）
    intensity_curve             # 威胁强度随 tick 的曲线
  }

  events[]                      # 预脚本化事件：
    { when, what, once? }       #   复用 Logic DSL 触发机制

  objectives {
    win[] / lose[] / scoring[]  # 胜负与超时评分
  }

  constraints {
    capability_manifest         # 能力清单上限（对接 World Rule §22）
    complexity_budget           # 复杂度预算（对接 §23）
    time_limit                  # 回合上限
  }
}
```

三个要点：

1. **事件复用 Logic DSL**。GM 不发明第二套脚本系统——
   `WHEN turn >= 20 AND zone == danger THEN heat_gain +50%` 和一个炮塔的
   逻辑是同一种东西。
2. **威胁是曲线，不是固定值**。开局温和、随时间升级——开疆拓土自带时间压力。
3. **恩赐是阀门**。组件、物料、能量给多少，直接决定创造的自由度，
   这是 Complexity Budget 在场景层的落地。

# 3. 世界生成 Genesis

从 `场景包 + seed` → 初始 World State。

## 3.1 地形生成走五行

程序化生成（未来）不是噪声涂色，而是按法则生成——
**让地图本身说法则的语言**，Agent 观察地貌就能推断资源与危险：

```text
第一步  基底阴阳场（低频噪声）
        → 决定每格的阴阳偏向

第二步  五行填充
        阳极 → 火地      阴极 → 水泽
        中和 → 土地      次强 → 金地 / 木林

第三步  相生梯度
        相邻格偏向"生"关系过渡（火地渐变为土地，而不是突跳为水泽）
        → 地貌连续，符合直觉

第四步  相克边界
        克关系相邻处产生"冲突地貌"
        → 水火交界 = 迷雾泽；金木交界 = 荒铜林
        → 有趣的位置在法则上自洽，不是随机撒的
```

v0.1 的手工地图也按这四步的原则画。

## 3.2 资源分布

资源 = 五行物料，分布跟随地形偏向：

```text
火地  → 火行物料
水泽  → 水行物料
金阴区 → 金行矿
木林区 → 木行料
土地  → 土行料（最常见，基础建材）
```

稀缺度设计原则：

> **克制手段应当比基础物料稀有。**

水克火用的寒髓、火克金用的烈晶——如果遍地都是，
克制就退化成常识；如果必须开疆获得，克制就成了**战略目标**。

## 3.3 初始感知与旧地图

```text
出生点周围 N 格 = 初始已知
其余 = 雾：不是"黑"，是"未观测"（与知由感律一致）
```

恩赐里可以包含**旧地图**（prior_knowledge）：

- 标注部分区域的先验信息（资源方位、地形）
- 但**可能过期**——地形会变、资源会被采空、敌人会移动

于是从第一回合起就有一个真实决策：

> 信旧图，还是信传感器？

过期信息是这个世界的合法入口（知由感律不禁止记错，只禁止无中生有）。

# 4. 探索与地图发现

> 本游戏的形状是**单角色 RPG + 创造**：玩家 + Agent 控制一个角色，
> 回合制战斗、采集、造工具、变强、完成任务。
> "开疆拓土" = 逐步发现地图（如经典 RPG 的迷雾探索），不是领土控制。
> 据点 / 领土 / 生产链属未来扩展（见 §9）。

## 4.1 雾与发现

```text
未观测（雾）→ 途经 → 已探明 → 记入 Agent 自己的记忆
```

- 雾不是"黑"，是"未观测"（知由感律）。
- Engine 不替 Agent 记地图：走过的地方记不记得，是 Agent Runtime 的事
  （World Rule §21：Memory 不属于 World Engine）。
- 地图发现进度是**认知状态**，不是世界状态。

## 4.2 发现的收益与成本

```text
收益：资源点、遗迹、任务地点、视野、更优路线
成本：时间（时有序律）、能量、暴露、危险
```

侦察受阴阳曲线约束：

```text
主动扫描（阳）：看得远，但生热、显迹——等于告诉附近敌人"我在这"
被动观望（阴）：安全省气，但慢，视野窄
```

## 4.3 深度分层

地图按离安全区的距离自然分层（RPG 的区域难度）：

```text
外环（土性，安全）→ 中带（混合地貌，弱敌）→ 深处（极端五行区，强敌与稀有资源）
```

稀有资源在深处（§3.2：克制物料比基础物料稀有）——
**探索深度 = 收益与风险的同一把刻度尺**，这是 RPG 式探索的内在驱动力。

# 5. 敌人生成谱系

## 5.1 四级谱系

```text
Tier 0  手摆实体         场景包直接定义 + Logic 驱动           v0.1
Tier 1  Logic 脚本种群   行为模板 + 参数变体（游荡者/哨卫/掠食者） v0.1–0.2
Tier 2  程序化生成表     按地形偏向 × 阴阳周期 × 威胁曲线撒      v0.2
Tier 3  LLM 设计敌人    LLM 产 Blueprint + Logic              未来
        → 引擎静态校验 → 试跑平衡 → 绑版本 → 进场景包
```

Tier 3 意味着：**敌人也进入"创造"玩法**。
未来玩家Agent 会遇到另一个 LLM 设计的、通过验证的敌人——
对抗的深度随模型能力共同进化，但世界不变（World Rule §25 的精神）。

## 5.2 敌人设计的铁律

```text
一、敌人是 Entity。没有特例物理：
    同一条克曲线、同一条阴阳曲线、同样会过热、同样怕水。

二、敌人没有特权 AI。v0.1 敌人智能只能是 Logic DSL（决定性）。
    未来可以挂小模型，但必须走 Agent Protocol（Intent → Engine），
    不允许直接改世界。

三、敌人是诚实的。信号迹不说谎：
    火行敌人必有火迹，金甲必有回波。
    世界不撒谎，但可以藏——藏本身就是法则允许的（阴）。
```

第三条是对"暗黑 RNG"式游戏设计的明确拒绝：
**敌人不靠掷骰子变强，玩家输给的是判断，不是运气。**

# 6. 威胁曲线与难度参数

```text
threat_intensity(t) = base + ramp × t + spikes[]     # spikes 来自 events[]
```

场景包可调的难度旋钮：

```text
威胁基数 / 成长率        敌人强度与密度
资源稀缺度               物料总量与克制物料稀有度
恩赐规模                 组件 / 物料 / 能量预算
能力上限                 manifest 与 complexity_budget
时间压力                 回合上限、阴阳周期
```

平衡原则：

> 压力主要来自**时间与能量**（法则资源），
> 其次才是敌人（对抗资源）。

这保证游戏的底色是"生存与创造"，而不是"刷怪"。
敌人是地图上的**问题**，不是游戏的**主体**。

# 7. 决定性与 Replay

一局的完整决定性来源：

```text
ruleset 版本   world-rule/0.1 + world-laws/0.1
             + component-set/0.1 + scenario/1.0
seed           程序化生成的随机源
Intent 流      所有 Agent（含敌人、含未来的 LLM 敌人）的 Intent 序列
Guidance 流    所有玩家干预（类型、内容、时间戳）
─────────────────────────────────────────────
= 可精确重放
```

两条硬规则：

```text
一、Replay 不重跑任何 LLM。
    回放器 = Engine + 输入记录。存档 = World State 快照 + 后续 Intent 流。

二、局中没有任何未版本化的随机源。
    一切"随机"来自 seed 驱动的伪随机，一切事件来自预脚本化触发器。
```

## 7.1 无限世界的重放（v0.4 前瞻）

```text
无限世界按 chunk 确定性生成：(seed, 坐标) 纯函数，同一输入永远得到同一 chunk。
chunk 生成不消耗对局 Rng：地形生成与对局随机流相互独立，回放中途生成新 chunk 不扰动已发生的随机序列。
重放仍然 = Engine + seed + Intent 流 + Guidance 流，§7 的两条硬规则原样成立。
```

> 详细设计见 docs/specs/2026-09-18-v04-infinite-hex-design.md

# 8. 场景包 #1：MVP

《Player Experience & MVP v0.1》的世界，正式落为第一个场景包：

```text
scenario/mvp-0.1        seed: 固定

world:
  12×12；30 回合上限
  外环        土性中性
  北区遗迹    金阴偏向（寒冷蚀能、硬物回声强）
  中央危险区  火阳过盛（耗气、生热、迹显）
  水泽        可选（v0.1 可省）

genesis:
  玩家 Agent 出生：西南角（土地，安全）
  组件恩赐：Light Frame（金或木，赛前选）、Small Battery（土）、
            Basic Motor（木）、Optical Sensor（水）、Processor L1（土）
  物料恩赐：少量土/木/金料——够造 1~2 个小型装置或修复
  Fragment：中央危险区深处
  旧地图：标注 Fragment 大致方位（先验，可能不准）

threats:
  Unknown Agent ×1：火迹明显但实为低威胁采集者
                    Logic：游荡 + 遇险则避让（确定性脚本）
  环境威胁：危险区每 tick 耗气 + 生热（= MVP 的"环境损耗"）

events:
  turn ≥ 20：危险区热度上升（阴阳周期 mini 版 → 时间压力）

objectives:
  win：  携 Fragment 返回出生点
  lose：  Integrity ≤ 0
  超时：  按目标完成度评分

constraints:
  complexity_budget：assembly max_components 8
  Influence 数值不在本层——归 MVP 文档（体验层）
```

注意两个语义升级（相对 MVP 文档原文，无冲突）：

```text
一、环境损耗 = 火阳过盛的地形效果（法则层早已解释它，此处挂上钩子）
二、"检测到 Unknown Agent 有远程威胁感" = 火迹明显（采集者背着发热设备）
   —— 它其实不是战士，是虚张声势的邻居
```

# 9. 未来扩展：策略层（当前版本不做）

以下内容不属于 v0.x，写入此处只为标记方向——对应《World Rule》§25 的
Stage 4+（游戏从"单角色 RPG"演进到"系统设计师 / 文明阶段"时才解锁）：

```text
据点系统    信标 / 炮塔 / 仓库 / 矿机（全是 Logic 实体，同一套物理）
领土        感知 + 火力 + 补给的物理覆盖，涌现而非登记
生产链      相生链的工厂化：让机器制造机器
多人对抗    竞技场场景包：双方恩赐与出生点对称
```

届时依然有效的设计约束：

```text
据点也是 Entity，没有特例物理
没有"安全区"特例，只有"守不守得住"
```
